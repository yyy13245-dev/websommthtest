工作原理与名词说明 AI 生成

N 是什么？N 就是屏幕上点的数量（点数）。这是本工具唯一的自变量，其余全部由它推导：

① 生成 N 个随机点，坐标随时间缓慢移动CPU 计算
② 把每两个点之间都连一条线（全部互连，不剔除）GPU 光栅化
③ 连线总数 = N × (N−1) ÷ 2O(N²) 增长

为什么是 O(N²)？因为真实业务里的"关系图 / 力导向图 / 碰撞检测 / 全连接网络"都是两两相连。N 从 50 涨到 5000，连线数从 1,225 涨到 12,497,500——一万倍。这条曲线足够陡，能把任何设备的性能拐点逼出来；而点数的计算量只是 O(N)，相对平缓，不会掩盖 GPU 的瓶颈。

一次测试怎么跑？

① 探测刷新率50 帧，约 0.8 秒
② 预热（可选，默认 3 秒）让 JIT / 着色器 / 频率到位
③ 逐档测试：N 从起始值按步长递增每档连续画若干帧
④ 每档重复 1–5 次，取中位数抗偶发干扰
⑤ 汇总出报告图表 + 明细表 + 评级

档位 = 一个具体的 N 值。比如「起始 50、结束 1000、步长 50」，就是依次测 N=50、100、150…1000，共 20 档。

四个指标分别是什么？

掉帧率：单帧耗时超过一帧预算（60Hz 屏 = 16.7ms）的比例主指标
拐点：平均帧率首次跌破 60fps 的那个 N还能塞多少点
GC 抖动：既不是计算也不是提交的"凭空耗时"回收 / 模糊 / 重绘
外推极限：用轻负载段拟合出的理论上限未触顶时使用

为什么用掉帧率而不是平均 FPS 当主指标？平均 FPS 会被屏幕刷新率"截断"——120Hz 屏最高就是 120，240Hz 屏最高就是 240，两台都跑满的设备平均值完全一样，分不出高下。而掉帧率衡量的是"相对自身预算超标了多少"，与刷新率无关，跨设备可比。拐点精度 ≈ 步长的一半，步长 50 就是 ±25 点。

两种代码写法有什么区别？

优化写法：对象池、VBO 驻留、一次 beginPath 画完所有线测"设备极限算力"
普通写法：每帧新建对象、逐线 beginPath、开阴影模糊测"遇到平庸代码的余量"

同一台设备，优化写法可能评到 A，普通写法只有 D。这两个分数都对——前者告诉你"代码写好了能跑多快"，后者告诉你"代码没写好还剩多少"。两列之间的差距，就是前端性能优化的收益空间。

三个渲染器测的分别是：软件渲染 → CPU 算力；WebGL 1.0 → GPU 光栅化基线；WebGL 2.0 → GPU 现代路径（原生 32 位索引 + gl_VertexID，顶点带宽少 25%）。不支持的渲染器按钮是灰的，点不动。

一句话：本工具不联网、不上传、不追踪，所有数据只存在你自己的浏览器里。

1. 我们收集什么？
什么都不收集。本工具是纯静态单文件网页，没有服务器、没有后端接口、没有账号系统。把它复制到 U 盘、断网打开，功能完全正常。已通过代码审计确认：零外部链接、零 fetch / XHR / sendBeacon 请求、零第三方统计脚本（无 Google Analytics、无百度统计、无 Sentry 等）。

2. 数据存在哪里？
全部保存在你浏览器的 localStorage（本机存储）里，共 7 个键：pcbench_last（上次结果）、pcbench_hist（最多 30 条历史）、pcbench_theme（主题）、pcbench_accent / pcbench_accent2（自定义配色）、pcbench_dense（紧凑模式）、pcbench_cfg（配置副本）。这些数据不会离开你的设备，只有你自己能看到。

3. 会不会上传我的硬件信息？
不会。测试会读取显卡型号（用于识别软件渲染）、CPU 核心数、屏幕刷新率、电池状态，但这些信息只显示在屏幕上给你看，不会发送、不会记录、不会用于任何统计。硬件加速检测只调用浏览器本地的 WEBGL_debug_renderer_info 接口。

4. 怎么彻底删除我的数据？
三选一：① 在「9 本机测试历史」卡片点「清空全部」；② 清除浏览器缓存 / 网站数据；③ 使用无痕模式打开（关闭窗口即自动清除）。卸载本工具只需删除这一个 HTML 文件。

5. Cookie 与追踪
不使用 Cookie，不做指纹识别，不跨站点追踪。本工具无法也不会识别你的身份。
